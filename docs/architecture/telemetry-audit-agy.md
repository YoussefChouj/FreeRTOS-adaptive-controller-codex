### Producers & Framing
- **Firmware Telemetry Producers**:
  - `TASK/send_data.c:635` (`Send_Groundstation_Telemetry_UART4`): Generates legacy Frame A (`0x01`, MRAC inner loops + status, 48 B), Frame B (`0x02`, MRAC weights + 12 PID loops, 326–333 B), Frame C (`0x06`, attitude + gyro + pos + RPM, 54 B, CRC16-CCITT), SysID (`0x03`, 43 B), and OF calibration (`0x05`, 62/82 B). Emitted over UART5 via `DMA1_Stream7`.
  - `TASK/send_data.c:489` (`usart3_send`): Polled JustFloat attitude frame (16 B, IEEE-754 tail `\x00\x00\x80\x7f`) on USART3; stood down when `Subscribe_StreamOwnsUsart3()` (`TASK/send_data.c:508`).
  - `API/subscribe.c:386` (`Subscribe_StreamTick`): Emits dynamic streaming data frames (`0x09 + slot`) over USART3 TX ring (`DMA1_Stream3`) or UART5 (`DMA1_Stream7`). Frame contains 6 B header + 1 B per-slot sequence + 4 B source time (`T_MS = xTaskGetTickCount()`) + raw bytes + 2 B CRC16-CCITT (`API/subscribe.h:128-134`).
- **Command & Ingress Path**:
  - USART3: `TASK/stm32f4xx_it.c:115` (`USART3_IRQHandler`) receives IDLE-line interrupt, passes DMA buffer to `Handle_USART3_GroundStation_Command` (`BSP/usart5.c:487`), setting `Subscribe_RxTransport = USART3`.
  - UART5: `BSP/usart5.c:465` (`Handle_UART5_GroundStation_Command`) gates on `SUBSCRIBE_UART5_ENABLED` (disabled by default in production).
  - Parser `ParseGsCommandFrames` (`BSP/usart5.c:425`) routes:
    1. Legacy commands `0xCC 0xDD [CMD][IDX][float32 LE][CRC8]` (`BSP/usart5.c:328`) into `gs_cmd_queue[16]`.
    2. Versioned transactions `0xCC 0xDF [VER][FLAGS][TX_ID_LE16][CMD][IDX][LEN_LE16][PAYLOAD][CRC8]` (`firmware/command_protocol.c:64`) into `gs_cmd_queue` with transaction metadata.
    3. Subscribe & Discovery requests `0xCC 0xDE [CMD][LEN_BE16][MAX_NUM_BASIS][PAYLOAD][CRC8]` (`BSP/usart5.c:197`) staged into `UA5RxSubscribeBuf`.
  - `TASK/send_data.c:1377` (`Process_GroundStation_Command`): Consumes `gs_cmd_queue`, runs safety checks (`CommandSafetyReject`), applies parameters, and emits ACK (`0x30`), REJECTED (`0x31`), or APPLIED (`0x32`) via `SendTransactionResult` (`TASK/send_data.c:1344`).

### Schema/Registry Discovery, DWARF, and Build-ID
- **Static Platform Registry**: Single source of truth is `registry/platform_registry.yaml`. Code generator `scripts/generate_platform_registry.py:23-100` computes CRC32 digest (`zlib.crc32`) and generates `firmware/platform_registry_gen.h`, `firmware/platform_registry_gen.c`, and `ground_station/generated/platform_registry.json`.
- **Over-The-Air Discovery**: Host sends `0xCC 0xDE 0x22` (`PLATFORM_DISCOVERY_CMD`) or `0x23` (`PLATFORM_REGISTRY_DIGEST_CMD`). Firmware builds binary discovery frame (`firmware/platform_registry.c:68`) containing magic `'UAVR'`, protocol versions, capability bitmask, `PLATFORM_REGISTRY_CRC32`, `build_id[4]`, hardware UID, reset cause, and stream limits. Parsed on ground station by `ground_station/platform/discovery.py:80`.
- **Ground-Side Variable Learning**: Host uses `ground_station/livewatch/symbols.py:63` (`SymbolResolver`) to parse DWARF debug sections directly from Keil output `OBJ/JX_FLY.axf` via `pyelftools`. Resolves dotted paths (`s_ekf.x[2]`, `mrac_state.roll.Theta[1]`) to physical 32-bit addresses and C types with zero hand-coded memory maps.
- **Build-ID / ELF Verification**: `ground_station/flashtool/build_id.py:10-43` stamps a 4-word identity (`0xB10DCAFE`, build counter, epoch timestamp, source tree SHA-256 fingerprint) into `OBJ/build_id.c` compiled into firmware `.data`. Ground station verifies `build_id` against `.build_identity.json` via pyOCD SWD (`ground_station/flashtool/safe_flash.py:24`, `ground_station/livewatch/verify.py`) and over WiFi discovery (`ground_station/platform/discovery.py:48`).

### Firmware CPU, RAM, and Stack Costs
- **Stack Budget**: `SENDTASK_STK_SIZE = 500` words (2,000 bytes) (`USER/main.c:198`, `API/subscribe.c:18`). Max allowed stack local is 32 bytes (`API/subscribe.h:45`). All buffers (`tx_buf[512]`, `err_buf[256]`, `s_streams[4]` ~2,032 B, `s_tx_ring[4096]`) are file-scope statics in BSS/Data.
- **CPU Overhead & Pacing Bottleneck**:
  - USART3 uses DMA continuous ring with quick IRQ hand-offs (<2 µs critical section PRIMASK disable, `BSP/usart3.c:292-322`).
  - **The UART4/5 DMA Busy-Wait**: In `SUBSCRIBE_TELEMETRY_MIXED` mode (default), `TASK/send_data.c:666,1260` executes synchronous polling: `while (DMA_GetCurrDataCounter(DMA1_Stream7));`. For a 43 B frame at 115200 baud, this spins for ~3.73 ms; for Frame B (326 B), it spins for 26.5 ms. Preemption by 1 kHz IMU task stretches this further, dropping Send_Task loop frequency from nominal 200 Hz to **80.4 Hz** (`API/subscribe.h:254`).
- **Contention Between Links**:
  - Physical DMA streams are independent: USART3 uses `DMA1_Stream1` (RX) and `DMA1_Stream3` (TX); UART5 uses `DMA1_Stream0` (RX) and `DMA1_Stream7` (TX).
  - Logical Contention: `UA5RxSubscribeBuf[256]` and `Subscribe_RxTransport` (`BSP/usart5.c:38,48`) are shared global statics. If an IDLE interrupt arrives on USART3 while a UART5 request is pending in Send_Task, `Subscribe_RxTransport` is overwritten, misrouting the reply (`API/subscribe.c:358`).
  - Debugger Contention: PyOCD SWD access and UART5 VCP share the exact same physical CMSIS-DAP USB endpoint. Running pyOCD SWD while streaming UART5 causes bus transfer errors.
- **Latency & Loss Handling**:
  - WiFi telemetry is UDP fire-and-forget. Sequence continuity is monitored via 8-bit wrapping `SEQ` (`API/subscribe.h:130`, `ground_station/service/telemetry_adapter.py:80`). Dropped packets are not retransmitted.
  - WiFi requires "the UDP nudge" (`docs/telemetry-protocol.md:24`, `ground_station/livewatch/transport.py:470`): MicoAir routes downlink UDP datagrams strictly to the IP:port of the most recent uplink datagram received.

### What is Automatic vs Manual
1. **Fully Automatic (DWARF Path)**:
   - Reading via SWD livewatch or arbitrary custom streaming (`stream_log.py --group "mrac_state.pitch.sigma"`) is automatic. `SymbolResolver` (`ground_station/livewatch/symbols.py:78`) reads `DW_TAG_variable`, calculates struct member offsets (`DW_AT_data_member_location`), array dimensions, and scalar formatting without touching C headers or ground station decoders.
2. **Requires Manual Edits**:
   - **Platform Registry & Typed Discovery**: Must add descriptor to `registry/platform_registry.yaml`, run `python scripts/generate_platform_registry.py`, and recompile firmware (`firmware/platform_registry_gen.c`).
   - **Logging Presets**: Must edit `ground_station/livewatch/manifests.yaml` and `multi_slot_presets.yaml`.
   - **Dashboard UI & Spec Mapping**: Must register DWARF-to-spec key in `ground_station/service/schema_registry.py:75` (or UI reads raw DWARF path). Dashboard panels (`docs/dashboard-platform/shell/plugins/*.js`) require custom JavaScript DOM rendering for new signals.
   - **Command Ingress**: Adding a new tunable parameter requires adding a command ID to `TASK/send_data.c:1410-1886` (`Process_GroundStation_Command`), updating `firmware/command_protocol.h`, and mapping in `ground_station/comm/serial_bridge.py`.

### What Breaks and How Drift is Detected
- **The Stale ELF Hazard**: In ARMCC V5, any change to global variables or compiler optimization relocates symbols in `.bss` / `.data`. If the ground station uses an un-flashed or older `OBJ/JX_FLY.axf`, address subscriptions resolve to incorrect memory locations.
- **Detection Mechanisms**:
  - `build_id`: Verified by `flashtool/safe_flash.py` and `livewatch/verify.py` over SWD. Also returned in discovery frame `0x22`. **Critical Gap**: `wifi_bridge.py` does NOT verify `build_id` before auto-subscribing on slot 0; it blindly uses local `OBJ/JX_FLY.axf` (`ground_station/comm/wifi_bridge.py:943`).
  - `PLATFORM_REGISTRY_CRC32`: Compared by `Discovery.compatible_with()` (`ground_station/platform/discovery.py:61`). Rejects schema drift if versions/counts do not match.

## 4. Agent Compatibility and Safety Gates

### CLI and API Accessibility
- **REST API (`ground_station/service/api.py:532,956`)**:
  - `/api/view-model`: Complete browser-renderable snapshot in JSON (slots, freshness, sequence, loss %, fault log, command history).
  - `/api/contract`: Fully typed machine-readable JSON schema of all platform descriptors, commands, units, and safety bounds (`ground_station/platform/firmware_contract.py:15`).
  - `/api/diagnostics/bundle`: Comprehensive provenance snapshot (Git HEAD, dirty state, ELF hash, schema ID, recent frames, view model, console logs) (`ground_station/service/api.py:778`).
  - `/health`, `/slots`, `/health/slots`, `/experiments`, `/artifacts`, `/sessions`: Full JSON endpoints.
- **Command-Line Tooling**:
  - `python -m ground_station.livewatch`: CLI subcommands (`manifests`, `budget`, `names`, `verify`, `stream`, `stream_log`).
  - *Gap*: Variable discovery CLI currently outputs newline-delimited text (`cli.py`), not JSON; full variable listing over HTTP without local AXF access is missing.

### Safety Gates & Interlocks
- **Firmware Command Gate (`TASK/send_data.c:1324-1342`)**:
  - `CommandSafetyReject()` rejects virtual RC stick injection (CMD `0x06`) and trajectory commands (CMD `0x0A` TWC, `0x0B` sinusoid, `0x0C` circle, `0x11` figure-8) unless `DroneStatus.FlyMode == FlyMode_SDK`.
  - Rejects recalibration (CMD `0x18`) unless in `FLIGHT_PHASE_GROUND_IDLE` and `DisArmed`.
  - CMD `0x16` (motor bench test) is locked to `DisArmed` state with a 500 ms heartbeat watchdog (`motor_test_watchdog`, `TASK/send_data.c:1873`).
- **Ground Station Authority Arbiter (`ground_station/platform/plugins.py:65-150`)**:
  - Single-owner token arbiter (`AuthorityArbiter`) with 500 ms heartbeat lease. Prevents multiple plugins or concurrent agents from injecting conflicting control commands.
- **EKF Shadow Isolation**:
  - `s_ekf` runs in `TASK/send_data.c:683-743` purely in shadow mode. Its outputs (`v_body`, `P_diag`) are piped to telemetry frame `0x05` but **never connected** to actuator outputs or attitude/position setpoints in `TASK/StabilizerTask.c`. Control loops remain locked to Mahony attitude and raw optical flow.
- **Non-Intrusive SWD Gate**:
  - `ground_station/livewatch/transport.py:205` uses pyOCD with `connect_mode=attach`, `target_override=cortex_m`, and `resume_on_disconnect=False`. SWD probes never reset, halt, or write core registers.

## 5. Division of Labour Between Links & Opportunities Left on the Table

### Current Division Assessment
- **WiFi (USART3 @ 921600 baud)**: Appropriately assigned as the primary operational telemetry downlink and command uplink. The 91.3 kB/s wire capacity provides 32× headroom over baseline telemetry (`docs/telemetry-protocol.md:279`). The 4,096 B TX ring absorbs Send_Task preemption jitter cleanly.
- **SWD / Wireless Debugger (UART5 @ 115200 baud)**: Appropriately assigned as the engineering recovery, non-intrusive memory inspection, and firmware flash plane.

### What is Left on the Table
1. **SEGGER RTT (Real-Time Transfer) via SWD**:
   - *Status*: **Completely unutilized**.
   - *Opportunity*: RTT uses up/down circular ring buffers in STM32 SRAM. Firmware writes to RAM in <1 µs (zero DMA busy-wait, zero UART baud limit). The wireless CMSIS-DAP probe can poll RTT buffers asynchronously via SWD at up to 500 kB/s. This could stream 1 kHz raw IMU data or 200 Hz inner-loop controllers without loading the MCU or taking WiFi airtime.
2. **UART5 Legacy Telemetry Dragging Firmware Cadence**:
   - UART5 legacy Frame A/B/C streaming is still active by default in `SUBSCRIBE_TELEMETRY_MIXED` mode, forcing Send_Task to busy-wait ~3.7 ms on `DMA1_Stream7`. This drags the entire task down to 80.4 Hz. Moving entirely to `SUBSCRIBE_TELEMETRY_SUBSCRIBE_ONLY` over WiFi immediately restores the 200 Hz control loop observation rate.
3. **The 256 B Asymmetric RX Bottleneck**:
   - While USART3 TX has a 4,096 B ring buffer capable of 90 kB/s, the RX DMA and mailbox buffers are artificially capped at 256 B (`BSP/usart3.h:38`, `BSP/usart5.h:12`). This prevents host subscribe plans exceeding 30 ranges from being received in a single frame.

### Strategic Roadmap Reordering Recommendation
- **Action**: Elevate **WP2 (Repair subscribe transport)** fixes for the **256-byte staging buffer** and **slot overwrite** to be tackled immediately in tandem with **WP1**.
- **Rationale**: Currently, the dashboard live view is completely starved of telemetry (`samples=0`, `active_streams=0`) because the slot-0 subscribe frame exceeds 249 bytes and is silently dropped by `BSP/usart5.c:241`. Attempting to implement or verify WP3 (semantic truth) and WP4 (workspaces/plugins) without live telemetry forces reliance on mock simulators rather than real wire truth.
