# Agent Map — deterministic project knowledge for agents

Status: SPEC, approved direction 2026-09-22. Replaces the proposed vector-RAG pipeline
(rejected; research digest in `scratch/rag_research/ark.md`).

## Why

The repo is ~15k lines of C + ~45k Python (~1M tokens). At this size grep + exact symbol
navigation beats embeddings (Claude Code, Cline and Sourcegraph all dropped vector indexes;
Cursor's gain appears mainly above 1,000 files). What agents lack is not search, it is the
**joins** between facts the project already holds in machine-readable form:

| Source of truth | Fact |
| --- | --- |
| clangd (`compile_commands.json`) / Serena | definition, references, callers, writers |
| DWARF in `OBJ/JX_FLY.axf` | address, type, `decl_file:decl_line` of each global |
| `ground_station/livewatch/multi_slot_presets.yaml`, subscribe protocol | streamable, rate |
| `GET /api/manifest` | dashboard panels, commands, telemetry names |
| `docs/glossary.md` | domain meaning |
| `docs/agent-map/modules.yaml` (hand-written, the only human input) | module purpose + safety tier |

Rules: **no LLM-generated metadata, no embeddings.** Everything except `modules.yaml` is
regenerated by a script, so it cannot hallucinate and cannot silently go stale.

## Deliverables (in order; each is one worker task, measured before the next)

### Step 0 — baseline (supervisor, no code)
Write `docs/agent-map/benchmark.md`: 10 questions agents actually ask, e.g.
"what writes `u_gyroy` and how can I watch it live?", "which task runs MRAC and at what rate?".
Record turns/tokens to answer each with grep + Serena only. Step 1 must beat this.

### Step 1 — generator + CLI (`ground_station/agent_map/`)
- `python -m ground_station.agent_map build` → `docs/agent-map/agent_map.json` (gitignored,
  regenerated). One record per firmware global/function:
  `name, kind, file, line, module, tier, dwarf{address,type,size}|null,
   streamable{preset,slot}|null, panels[], glossary|null, writers[]|null`.
- `writers[]` from a regex/ctags pass over firmware C (assignments to the symbol); clangd
  references are a later upgrade, not required for step 1.
- `python -m ground_station.agent_map explain <name>` → compact text answer (≤ 25 lines).
  This CLI is the universal interface: WSL workers have no MCP, so they must be able to use it.
- Reuse existing code: DWARF via the livewatch resolver, manifest via service code paths
  (read files directly; **never call the live service**).
- Stdlib + existing deps only. Tests with a synthetic fixture plus one test on the real ELF
  that is skipped if `OBJ/JX_FLY.axf` is absent.

### Step 2 — `modules.yaml` (operator confirms)

### Step 3 — dashboard MCP tool `explain_symbol(name)`
Wraps the step-1 function and adds the **live value** via the service's existing read path.
Read-only. Goes in `ground_station/service/agent_mcp.py`.

### Step 4 — tier enforcement
Plans in the agent approval queue that touch a tier-0 file require operator approval in every
autonomy mode; tier-1 → tier-0 data flow (e.g. `s_ekf` into control) is flagged. Enforced in
code, not prose.

## Navigation protocol (all agents — mirrored in AGENTS.md and .agent-ops/STANDING-RULES.md)

1. Exact name known → `rg`/grep, or Serena `find_symbol` when MCP is available.
2. Once step 1 exists: `python -m ground_station.agent_map explain <name>` before reading files.
3. Never search `stm32_lib/`, `FreeRTOS/`, `OBJ/` unless the task is about vendor code.
4. Check a file's tier before editing; tier 0 needs explicit task permission.
5. Report navigation failures (couldn't find X, wrong file) to `.agent_memory/frictions.jsonl`
   — that file is the evidence for reweighting.
