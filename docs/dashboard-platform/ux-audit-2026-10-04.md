## Information hierarchy (implemented)
1. **Always visible, never collapsible**: flight strip (top: ARM, MODE, BAT, RC, LINK age, campaign status, Pause/Land/Abort),
   agent mode pill + STOP (bottom centre), toasts (bottom right). Nothing flight-critical lives only in a tab or the sidebar.
2. **Sidebar (collapsible)**: recorder + notes + preset, gate bar (CONN DISARM FRESH SCHEMA CMD), Session, Alarms.
3. **Workspace tabs**, one home per panel: Overview (default), Experiments (Campaign = workflow B), Estimator, Control, MRAC,
   Telemetry, Paths, Bench, Replay, Diagnostics, Approvals, Terminal.

## Done in WP-39
- Sidebar Flight Status card and the `sb-*` ids removed (strip owns ARM/MODE/BAT; attitude/altitude moved into the
  Flight Status panel); `#card-cmd` and `#card-streams` removed.
- Streams / Bandwidth Manager / Slot Manager are tabs of one **Telemetry Slots** card (`PANEL_GROUPS` in index.html):
  What slots carry / Link health / Expert subscribe. Bandwidth's "Request Slot" form is gone (it sent empty ranges,
  which the bridge refuses for slots 1-3).
- Tokens (no raw hex/rgba; L3 lists them): overview, status, safety, path, time-series, telemetry explorer, streams, slot
  manager, bandwidth, FFT, alarms.js. Canvas/WebGL read tokens through `GSUI.tokenColor`.
- D2 alert model + D3 voice: `ui/alarms.js` (one registry). D4 preflight report in the Campaign panel. D5 drag a key
  from the Telemetry Explorer onto Time Series, named per-browser layouts.
