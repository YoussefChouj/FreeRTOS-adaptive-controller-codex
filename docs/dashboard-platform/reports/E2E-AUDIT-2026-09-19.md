An exhaustive end-to-end audit was conducted across the Ground Station Dashboard stack, combining offline test suites, live HTTP/REST endpoint probes, browser static asset verification, and live network socket verification against the powered-on drone over MicoAir WiFi (`192.168.4.1`).

* **Web UI & API Endpoints:** All 14 HTTP service endpoints return `200 OK`; all 16 JavaScript UI plugins load cleanly and pass syntax validation.

Additionally, the UI plotting panels look for legacy channel keys (`ch0`..`ch15`) that the backend schema registry does not populate, and command panels have semantic mismatches with `firmware_contract.py`.

Once the identified P0 fixes are applied, the dashboard will achieve end-to-end autonomous operation.

### 3.2. Connecting to Drone & Telemetry Flow
* **Subscribe Handshake:**
  - Upon connection, the ground station sends a `0x21` Subscribe Request targeting Slot 0.
  - The drone processes the request and responds with a `0x08` Schema Frame (196 bytes).
  - `SchemaRegistry` receives the schema, successfully parsing and registering 23 memory ranges and 54 variables for Slot 0.
* **Telemetry Streaming Breakdown (P0 Blocker):**
  - Following the schema, the drone streams `0x09` Telemetry Data Frames containing packed sensor readings.
  - **Frame Discard Defect:** In `ground_station/comm/wifi_bridge.py:2090`, the bridge calculates:
    ```python
    total_len = 5 + payload_len + 2  # = 7 + payload_len
    ```
    However, the firmware wire frame ([`API/subscribe.c:658-670`](file:///mnt/c/Users/Acer/Desktop/UAV_lab/FreeRTOS-adaptive-controller-codex/API/subscribe.c#L658-L670)) format is:
    `[0xAA][0xBB][TYPE][LEN_HI][LEN_LO][SEQ][T_MS_4B][VALUES...][CRC_2B]`
    Header (6 bytes) + Payload (`t_ms` 4B + variable bytes) + CRC (2 bytes) = **`8 + payload_len` (or `6 + payload_len + 2`)**.
  - `_parse_one()` slices 1 byte short (e.g., 206 bytes instead of 207).
  - At line 3437: `if len(frame) != 6 + payload_len + 2: return None`. The check fails and **silently drops 100% of data frames**.
  - The residual 1 byte remains at the head of `rx_buf`, throwing the parser out of sync and corrupting all subsequent frames.

### 3.3. Verifying Plots Display Data
* **Variable Key Mismatch (P0 Blocker):**
  - In `time-series-panel.js:21-27` and `fft-panel.js:17-22`, the panels look for channel keys:
    `ch0`, `ch1`, `ch2`, `ch10`, `ch11` under `state.streams['0'].values`.
  - The backend `TelemetryAdapter` and `SchemaRegistry` publish canonical telemetry paths (`status.roll_deg`, `status.pitch_deg`, `status.yaw_deg`, `status.vbat`, `mrac.roll_gamma`) and raw DWARF identifiers (`imu_data.rol`, `ahrs.rol`).
  - Because `ch0`..`ch15` are never emitted, the plots remain frozen displaying **"Waiting for data…"** indefinitely.

### 3.4. Verifying Command Dry-Run & Safety Path
* **ARM Status Visibility:**
  - `command-panel.js:9, 167` checks `state.streams[0].values.ch13` to evaluate ARM status. Because `ch13` does not exist, the arm state badge displays `UNKNOWN`, preventing operator safety awareness.
* **Quick Command Mapping Inversion:**
  - `command-panel.js:86-88` assigns Command ID `0x04` with payloads 0, 1, 2 to "Stabilize", "AltHold", "PosHold".
  - According to `ground_station/platform/firmware_contract.py` (`0x04: "FLIGHT_MODE_ABORT"`), CMD `0x04` is an Emergency Abort command. Calling it inadvertently aborts autonomous paths instead of changing flight modes.
* **Precondition Gating:**
  - `motor-bench-panel.js:287` issues direct calls to `api.submitCommand(CMD_ID_MOTOR_BENCH, ...)` without invoking `api.gatedCommand(..., ['disarmed'])`.
  - The backend `/api/actions` endpoint accepts commands, but `core.py:submit_command` lacks server-side contract validation against `FirmwareContract.validate_command`.

### 3.5. Verifying Logging & Replay End-to-End
* **Logging:**
  - `GroundService` initializes `SessionRecorder`, saving flight telemetry records to CSV and JSONL under `ground_station/logs/`.
  - File rotation, timestamp indexing, and schema metadata storage function as designed.
* **Replay Isolation (P1):**
  - Session replay records can be queried via `GET /sessions/<id>/records`.
  - In `replay-panel.js:300-410`, the playback scrubber renders frames into a dedicated canvas within the replay panel only. Replayed frames are not dispatched to the shared state bus or other panels (`time-series-panel`, `fft-panel`), isolating playback from the rest of the dashboard.

## 5. Prioritized Fix List (P0 / P1)

### P0 Fixes (Must Fix for Basic Operation)

#### 1. Fix Wire Framing Off-By-One Discarding 100% of Data Frames
* **File & Line:** [`ground_station/comm/wifi_bridge.py:2090`](file:///mnt/c/Users/Acer/Desktop/UAV_lab/FreeRTOS-adaptive-controller-codex/ground_station/comm/wifi_bridge.py#L2090)
* **Root Cause:** Slices frame using `total_len = 5 + payload_len + 2`. Firmware frame header is 6 bytes (`[AA][BB][TYPE][LEN_H][LEN_L][SEQ]`), making the total wire length `6 + payload_len + 2`. Slicing 1 byte short causes the validation assertion at line 3437 to fail every frame, dropping all telemetry and corrupting buffer alignment.
* **Required Change:** Change `total_len = 5 + payload_len + 2` to `total_len = 6 + payload_len + 2`.
* **Sizing:** **Small** (1 line change).

#### 2. Update Plotting Panels to Consume Canonical Telemetry Keys
* **File & Line:** 
  - [`docs/dashboard-platform/shell/plugins/time-series-panel.js:21-27, 208`](file:///mnt/c/Users/Acer/Desktop/UAV_lab/FreeRTOS-adaptive-controller-codex/docs/dashboard-platform/shell/plugins/time-series-panel.js#L21-L27)
  - [`docs/dashboard-platform/shell/plugins/fft-panel.js:17-22, 298`](file:///mnt/c/Users/Acer/Desktop/UAV_lab/FreeRTOS-adaptive-controller-codex/docs/dashboard-platform/shell/plugins/fft-panel.js#L17-L22)
* **Root Cause:** Both panels hardcode queries for `ch0`, `ch1`, `ch2`, `ch10`, `ch11` from legacy prototypes. The backend telemetry pipeline produces canonical variables: `status.roll_deg`, `status.pitch_deg`, `status.yaw_deg`, `status.vbat`, `ahrs.rol`, `ahrs.pit`.
* **Required Change:** Update `VARIABLE_DEFS` and `ANALYZE_VARS` arrays to resolve canonical keys, or implement a fallback key lookup in `TelemetryAdapter`.
* **Sizing:** **Small** (<20 lines in JS).

#### 3. Correct ARM Status Variable Reference in Command Panel
* **File & Line:** [`docs/dashboard-platform/shell/plugins/command-panel.js:9, 167`](file:///mnt/c/Users/Acer/Desktop/UAV_lab/FreeRTOS-adaptive-controller-codex/docs/dashboard-platform/shell/plugins/command-panel.js#L9)
* **Root Cause:** Reads `state.streams[0].values.ch13`. The actual ARM status is published under `status.arm` (or `DroneStatus.ARM_Status`). The badge permanently displays `UNKNOWN`.
* **Required Change:** Change lookup to `state.status?.arm ?? state.streams[0]?.values['status.arm'] ?? state.streams[0]?.values['DroneStatus.ARM_Status']`, and leverage `api.getArmState()`.
* **Sizing:** **Small** (<5 lines).

#### 4. Correct Quick Command ID Mappings (CMD 0x04 Inversion)
* **File & Line:** [`docs/dashboard-platform/shell/plugins/command-panel.js:86-88`](file:///mnt/c/Users/Acer/Desktop/UAV_lab/FreeRTOS-adaptive-controller-codex/docs/dashboard-platform/shell/plugins/command-panel.js#L86-L88)
* **Root Cause:** Panel buttons send CMD `0x04` for flight mode switching. In `firmware_contract.py`, `0x04` is `FLIGHT_MODE_ABORT`. Flight mode commands should use the dedicated flight mode command ID or parameter update.
* **Required Change:** Re-align quick command dispatch table with `firmware_contract.py`.
* **Sizing:** **Small** (15 lines).

### P1 Fixes (Robustness & Safety)

#### 5. Fix Missing Import in `livewatch verify` CLI
* **File & Line:** [`ground_station/livewatch/cli.py:175`](file:///mnt/c/Users/Acer/Desktop/UAV_lab/FreeRTOS-adaptive-controller-codex/ground_station/livewatch/cli.py#L175)

  - [`docs/dashboard-platform/shell/plugins/motor-bench-panel.js:287`](file:///mnt/c/Users/Acer/Desktop/UAV_lab/FreeRTOS-adaptive-controller-codex/docs/dashboard-platform/shell/plugins/motor-bench-panel.js#L287)

* **Required Change:** Wrap motor test buttons with `api.gatedCommand(..., ['disarmed'])`; add contract validation call in `GroundService.submit_command()`.
* **Sizing:** **Medium** (~35 lines).

#### 7. Propagate Replay Telemetry to Global State Bus
