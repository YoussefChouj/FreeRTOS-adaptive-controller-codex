# Dashboard and Firmware Review

Date: 2026-09-18  
Scope: running ground station on port 8081, dashboard source, Wi-Fi subscribe path, command dispatcher, and the STM32F4 firmware contract.

## Executive assessment

The project has useful building blocks, but it is not yet a dependable primary interface. The live service reports `connected=true` while `samples=0`, `active_streams=0`, and `last_update_ns=null`. The browser consequently renders a large stack of panels with blank values, contradictory safety states, demo data, and controls that can appear successful before firmware state has been observed. The next work must repair the data and truth model before adding more panels.

## Confirmed findings

| Severity | Finding | Evidence and consequence |
|---|---|---|
| P0 | Host slot-0 request can exceed firmware receive staging | `ground_station/comm/wifi_bridge.py:528-586` resolves 54 names to 54 one-element ranges and sends 442 bytes (`10 + 8*N`). `API/subscribe.h:189` advertises 62 ranges, but `BSP/usart5.h:12` and `BSP/usart3.h:38` allocate 256 bytes; `BSP/usart5.c:241,273` reject a frame above the buffer. This can prevent the schema and all dependent streams. |
| P0 | Slot-0 API ignores requested layout/rate | `wifi_bridge.py:654-660` replaces any nonzero slot-0 request with `_request_slot0_schema(layout="dashboard")`, including caller divider, ranges, and transport. Preview and apply can therefore describe different hardware actions. |
| P0 | Command semantics are unsafe to infer from labels | Firmware `TASK/send_data.c:1645-1688` defines 0x0F indices 0-12 as MRAC flags and 100-102 as telemetry modes; 0x04 is path abort/recovery per `COMMAND_SPEC.md`, while the UI command panel presents 0x04 values as Stabilize/AltHold/PosHold. Every command must be generated from one verified catalog and read back through a state machine. |
| P0 | Applied is reported without observed state | Firmware emits ACK at `send_data.c:1405-1407` and applies handlers later. The service and `safety-panel.js:138-170` treat HTTP submission/result as current parameter truth. A successful transaction is not a readback. |
| P1 | Transport ownership and pending request are ambiguous | `send_data.c:1294-1295` handles one global pending subscribe request; USART3/USART5 wrappers set a shared transport. A later ingress can change the reply route or overwrite/drop a request. This needs an explicit owner, queue, and request ID. |
| P1 | Freshness and schema identity are not strong enough | `/health` has `telemetry_schema_id=null` despite registry schema `r1-s1-9F32E2EA`; `core.py:417-441` snapshots schema/session but does not establish a typed runtime device/build identity. Unknown, stale, replay, and live values are not clearly separated. |
| P1 | Values are rounded in the service | `schema_registry.py:115-138` and `wifi_bridge.py:1693` round values for transport. This destroys precision needed for adaptive weights, covariance, bias, and parameter sweeps. Preserve raw numeric values; round only at presentation. |
| P1 | UI is one long panel stack with false or demo states | Browser observation at zero telemetry: Connected + “no telemetry”, motor controls enabled beside “Bench Mode Active”, safety badges “current” while values are `—`, and path animation marked DEMO MODE. These are dangerous ambiguities for a research vehicle. |
| P1 | Domain schema is stale/inconsistent | Existing telemetry docs describe EKF position channels, while `API/ekf.h` maps `s_ekf.x[0..2]` to velocity and bias states. The UI labels must come from firmware metadata, not hand-maintained channel assumptions. |
| P2 | Agent diagnosis is not reproducible | There is no single evidence bundle containing service provenance, firmware hash/ELF identity, wire frames, rendered view model, action journal, and screenshot. `STATE.md` contains contradictory completion claims. Agents can therefore report a code-level fix without proving the running UI. |

## What is verified working

SWD reads resolve live firmware variables; command 0x1E transitions `g_of_bias_mode` through FIXED/EMA/EKF; firmware contains MRAC feature flags and typed subscribe handlers; the service starts and command ACK/APPLIED frames are observable. These facts should be retained and covered by regression tests. Motor initialization remains deliberately excluded from validation.

## Review limits

This review did not issue a subscribe, command, flash, reset, or motor action. The running Python process had no visible command-line arguments, so log files and source provenance must be captured before attributing a live symptom to a particular checkout. The 442-byte request defect is source-confirmed and can be reproduced offline without hardware.
