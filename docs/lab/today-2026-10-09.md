# Today, step by step: fly your 3-layer MRAC (row 16) on the 570 g rope

Bottom line: flash once, fly a PID hover, then rows 16, 17, 18 (20 s hover each, rope only). Record each flight in
VOFA Studio: it saves a CSV and shows live plots in VOFA+ at the same time. Then run the review commands at the end.
Every expectation here is PROPOSED (replay and sim). Nothing has flown yet.

Think of it like a taste test: PID is the plain recipe, each vp row is one change to the recipe, and you taste them
one by one on the same plate (same rope, same battery level, same spot in the room).

## 0. What you need

| thing | where |
|---|---|
| a terminal in the repo folder | `D:\Projects\UAV_lab\FreeRTOS-adaptive-controller-codex` |
| Keil uVision | project `USER/JX_FLY.uvprojx` |
| VOFA+ | Start menu, VOFA+ |
| a full battery, the 570 g rope load, the RC | lab |

Two rules for the whole day:
- The dashboard (port 8081) and VOFA Studio both listen on UDP 14550. Only one of them runs at a time.
  VOFA Studio refuses to start while 8081 is up.
- You arm by RC. Nothing in software arms or spins the motors.

## 1. Close everything that holds the firmware or the radio link

Close the dashboard window, VOFA Studio, VOFA+, any `stream_log` terminal, and the Keil debug session.
(8081 locks the `.axf` file, so the flash fails if the dashboard is still running.)

## 2. Flash the new firmware (first build of the 3-layer code)

Plug in the ST-Link, power the drone, then run:

```bash
python -m ground_station.flashtool.rebuild_and_flash --yes
```

It must end with exit code 0. If it prints an error or exits non-zero, stop and paste the output to the next session.
Never add `--force`.

Check that the build has the 3-layer variables. The two studio preset tests turn green only on a 3L build, because
rows 16-19 log `pe`, `e_int`, `Phi_f` and `p_gain`:

```bash
python -m pytest -q ground_station/vofa_studio
```

Expected: all pass. If `test_shipped_presets_fit_budget` still fails on `vp16`..`vp19`, the flash did not build 3L:
stop and report it.

## 3. Pick the MRAC row in Keil

1. Open `USER/JX_FLY.uvprojx` in Keil.
2. Start a debug session (Debug, Start/Stop Debug Session, or Ctrl+F5). Do not press Download (F8): that reflashes.
3. Click Run (F5) so the firmware keeps running.
4. Open View, Watch Windows, Watch 1. Add `vp_id`, `vp_active` and `vp_user`.
5. Type the row number into `vp_id` (start with `16`). Within a second, `vp_active` must show the same number.
   - `vp_active = 0xEE` (238) means a field was refused. Do not fly that row.
   - Rows 7-15 need the MULTI build. On a default build they show 0xEE.
6. Fly with Keil attached the same way you did on 10-08 (load-test runbook, section 2). A reboot or pack swap
   resets the row to 0, so set `vp_id` again after every pack swap, on the ground and disarmed. Slot 3 of the log
   records `vp_active`, so the review shows which row really flew.

## 4. Start the logger and live view (once per flight)

```bash
python -m ground_station.vofa_studio
```

A browser page opens at http://localhost:8090. Then:
1. Pick the preset of the row you set, for example `vp16_3lv2_full`.
2. Type a session name containing the row and the load, for example `vp16_rope_01`. For the PID flight use
   `pid_rope_01`. The review tools read the row and the load from this name: `vpNN` or `pid`, and `arm` for the
   293 g arm (otherwise they assume the rope).
3. Choose mode `unlimited` (no timer), then press Start.
4. Open VOFA+, choose the UDP data source on port 1347 with the FireWater protocol, and you see live channels:
   pitch/roll setpoint and actual, u_nom, u_ad, the four motors, and altitude (rows 16-19 also show `pe`).

Files land in `logs/vofa/<name>.slot0.csv` .. `slot3.csv`, plus `<name>.meta.json`.

## 5. Fly (same pattern every time)

| # | row (Keil `vp_id`) | ch8 (MRAC on motors) | preset / session name |
|---|---|---|---|
| 1 | any, e.g. 16 | OFF = PID only | vp16 preset, name `pid_rope_01` |
| 2 | 16 (your 3-layer) | ON | `vp16_3lv2_full`, `vp16_rope_01` |
| 3 | 17 (L2 only, replay best) | ON | `vp17_l2_only`, `vp17_rope_01` |
| 4 | 18 (16 + self-tuning gain) | ON | `vp18_3lv2_dgain`, `vp18_rope_01` |
| 5 | repeat the best one | ON | `..._02` |

For each flight:
1. Load on the rope, drone at the room origin (fence |x| 1.6 m, |y| 2.0 m).
2. Start the session (step 4).
3. Arm by RC, take off, hover about 20 s, then land.
4. Disarm, press Stop in VOFA Studio.
5. Swap rows with Keil (step 3) between flights, always on the ground.

Abort (land at once) if:
- it tilts or drifts more than it did under PID;
- `u_ad` sits at its limit for more than 1 s (a flat line in VOFA+);
- the motors sit near 100% (the sim showed 16-20% saturation with the rope).

Row 19: rope hover only. Never on the 293 g arm, never while dropping or swapping the load.


Compare all of today's flights in one table: run the review once per flight with `--no-plots`, then the meta table:

```bash
python -m ground_station.analysis.adaptive_review logs/vofa/pid_rope_01 --out docs/flights/plots/2026-10-09-day/pid_rope_01 --no-plots
```

## 7. What the vp rows differ in, and how to tune by hand

Rows 2-15 all start from V1. Each row adds one thing:

| row | name | difference |
|---|---|---|
| 0 | flown S6 | the law that flew in September, gamma 1.0 |
| 1 | S6 x0.25 | row 0 with gamma 0.25 |
| 2 | V1 | reference model on, drive normalisation, e_dot term, gamma 0.25 |
| 3 | V2 | + soft saturation mu_sat 0.85 |
| 4 | PR | + kappa 0.5, crm 10 |
| 5 | ST | + st_eps 2 |
| 6 | 3L layer 1 | + lam_ang 4 (angle-error drive) |
| 7-11 | feature sets | row 6 with a bigger basis: S10, RBF12, RBF6, RBF24, S6+RBF12 (MULTI build only) |
| 12-15 | combos | S10X+PR, RBF24T, RBF24D, S10X+RBF16 (MULTI build only) |
| 16 | 3L-v2 (yours) | row 6 + layer 2: learns from prediction error, gamma_c 20 |
| 17 | L2 only | row 16 with tracking-error learning off on pitch/roll, gamma_c 8 (best in replay) |
| 18 | 3L-v2 + D | row 16 + self-tuning gain, p_max 4, p_forget 0.5 |
| 19 | L2 only + D | gamma_c 20, p_max 20, p_forget 5 (rope hover only) |

Measured replay (5 PID logs, pitch/roll; closer to 0 is better):
- vp6: -1.16 / -1.59
- row 16: -0.11 / -0.15
- row 17: -0.03 / -0.05

Your original layer 3 (task priors) is not built. Layer 2 band gating lost in the 10-05 sim and was replaced by the
prediction-error learning.

### Manual tuning: the user row (vp 100)

1. In the Keil watch window, expand `vp_user`. It starts as a copy of row 16.
2. Change one field.
3. Set `vp_user_go = 1`. `vp_active` must show 100; 0xEE means refused.
4. `vp_id = 16` returns to the table row.

It applies on the ground, or in flight while ch8 is off.

| field | does | row 16 | try (PROPOSED) |
|---|---|---|---|
| `g` | tracking-error learning rate | 0.25 | 0.1-0.5; every variant tipped at 1.0 in SIL |
| `te_off` | 1 = tracking learning off on p/r | 0 | 0 or 1 |
| `lam_ang` | how hard the angle error drives learning [1/s] | 4 | 2-6 |
| `gamma_c` | layer-2 learning rate [1/s], 0 = off | 20 | 4-20 |
| `p_max`, `p_forget` | self-tuning gain, 0 = off | 0, 0 | 4/0.5 (row 18) |
| `b_axis` | measured plant gain | 49 | leave it |
| `pe_delay` | ticks of command delay; 7 = 35 ms, the cap | 7 | leave it |
| `wc_pe` | layer-2 filter [rad/s] | 20 | 10-30 |

Change one field per flight, and only one step from the last value that flew well.
