# Run sheet 2026-10-14: drift, pad landing, then four xy controllers

Goal, in three phases:
- A: fix the drift once and for all.
- B: make pad landings repeatable.
- C: fly PID, tuned_shift, LQR and MPC on the same track and pick the best.

Each flight is one `.fly` script in `ground_station/service/campaigns/`. Every pass mark is PROPOSED: none has been measured yet. The plan was agreed in chat on 2026-10-14 (grilling Q1-Q11).

**What each script sets.** Each script writes VAR 44 (`g_xy_ctrl_kind`), 45 (`g_traj_ff_shift_s`) and 46 (`g_land_xy_gate_cm`) on the ground, before IDLE. These are its `set` line before `takeoff` (5ab96dd3+). Because the script sets all three, a pack swap that reboots the drone cannot leave an old value behind.

**When a write fails.** If the drone does not acknowledge a write, the takeoff is refused and the runner names it: `refused = set <name>`.

**Fusion mode.** It switches once only: mode 2 for A1, then mode 3 from A2 to the end.

**The tracks**, all from a 0.5 m hover:

| Phase | Track | Length |
|---|---|---|
| A | hold 70 s | |
| B | goto (0.4, -0.3) for 3 s, back to hover, then a gated land | |
| C | 0.4 m x step (4 s), circle r30, figure-8 a30, gated land | about 60-70 s, PROPOSED |

A top-level `goto` always flies out and back to the hover point, so the track needs no "goto 0,0" line.

## Bring-up (once, drone disarmed on the pad)

1. **Flash.** Stop 8081 (it locks the axf). Run `python -m ground_station.flashtool.rebuild_and_flash --yes`. Never use `--force`, and stop if it exits non-zero. Start 8081 again with `python -m ground_station.service --port 8081`.
   - The firmware must hold f1ed2c65 (land gate at the SETTLE dwell), a14f67e7 (MPC) and bff1d29f (VAR 44/45).
   - 5ab96dd3 and d2485ca9 are ground station only.
2. **Link check, 10 s.** Stream the C set at 100 Hz (core + velocity_loops + camera_fusion, 60 vars). Watch for drops.
   - If it drops, fly C at 50 Hz: change `rate 100` to `rate 50` in the four `lab_c_*` files.
   - This link has not been measured: it is UNVERIFIED.
3. **Camera.** `bash ground_station/lab/camera_truth.sh check` must print `ready 1920x1080`.
4. **Phone pose.** Re-check it first: on r7_f6 the marker shifted 157 px.
5. **Fusion.** `bash ground_station/lab/camera_truth.sh fusion r8_a1 2 --yaw-deg 94` for A1.
   - From A2 on, mode 3, for example `fusion r8_a2 3 --yaw-deg 94`.
   - Run `stop <name>` after each landing.

| Axis | idx (Kp, Ki, Kd) | Kp | Ki | Kd |

## Cooldown debrief (600 s, after every landing)

Every debrief follows the same routine:
1. Read the 5-line terminal debrief.
2. Look at the VOFA+ variables below together.
3. Pull out one lesson.
4. Pick the next flight.

The full debrief is `python -m ground_station.analysis.flight_debrief <outputs dir> --run <run folder>`. Its `debrief.md` holds the "Setpoint moves" table.

| Phase | VOFA+ variables | Question it answers |
|---|---|---|
| A | `cam_ex`, `cam_ey` (camera minus EKF), `corr_x`, `corr_y` (applied correction), `cam_ok` / `cam_rej`, `cam_age_ms`, `locxPID.FB`, `locyPID.FB` | Does the camera pull the EKF back, or does the EKF wander and the camera get rejected? |
| A | truth displacement over 60 s; `camera landing x/y cm` line | The pass mark, plus the landing offset without the gate |
| B | `g_wfb_status.prim_state` (in the log; a long SETTLE dwell = waiting for the camera), `cam_age_ms`, `cam_stale` | Did the gate wait for a fresh fix, or time out after 10 s? |
| B | `camera landing x/y cm` | The pass mark |
| C | `locxPID.Des` vs `locxPID.FB` at the 0.4 m step | Overshoot and settle time ("Setpoint moves" table) |
| C | `mymotor.motor1-4` / 4000 at the step, `volt` (`real_voltage`, updates at 1 Hz) | Was the controller short of thrust headroom (sag), or is the shape its own? |
| C | circle and figure-8 xy rms | The tie-break |

## Scoring C and failure branches

**Score.** Compare the 0.4 m step overshoot with today's PID (C1). Break ties on the circle + figure-8 xy rms. The winner is the lowest overshoot that beats PID on both. This rule is PROPOSED.

**Day drift.** If C5 differs from C1 by about as much as the controllers differ from each other, the day drifted too much. In that case the ranking is not trustworthy, so re-fly the close pairs.

**Failure branches:**

| If | Then |
|---|---|
| A2 fails | Debrief, fix on the ground (gains or fusion settings, operator picks in chat), then re-fly A2 before B. |
| A gate never opens in B | Read `prim_state` and `cam_age_ms`. The camera is lost or stale: check the tracker window and the phone pose. |
| An RC takeover happens | The flight does not count. Fly the same script again after the cooldown. |
