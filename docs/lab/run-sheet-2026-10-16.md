# Run sheet 2026-10-16: four xy controllers head to head

Plan agreed in chat on 2026-10-15: C3 fine-tuned PID vs ES auto-tuned PID vs LQR vs MPC, all on one track. The ES
auto-tune (in-flight CMA-ES, `livetune`) tunes both the roll/pitch rate loops and the xy position cascade.
Each flight is one `.fly` script in `ground_station/service/campaigns/` (`fly` from the repo root; the first flight needs
`--pack <1|2>`). Every pass mark and expected number is PROPOSED unless it says MEASURED.

F1, F4, F5, F6 fly the same track: 0.5 m hover, 0.4 m x step (4 s), circle r30, figure-8 a30, gated pad landing.
F2/F3: 0.5 m hover, `livetune` 85 s. Each window writes candidate gains, settles 2.5 s, chirps (rate: 1-8 Hz 30 deg/s;
pos: 0.3-2 Hz 20 deg/s on pitch for x, roll for y) and scores the error. Every end writes the defaults back; the best
gains are only reported (the runner's `livetune` summary line). Fairness: ES starts from the firmware defaults with
trust 0.3 (rate) / 0.6 (pos), and gets about 8 candidates per flight (C3 came from a long sim CMA-ES). If F3 is not
`recommended`, fly F3 again with `seed=1` before F4 (the CMA state does not carry across flights yet).

**Firmware on the drone:** 0e6e01b6, flashed 2026-10-15 22:05: D1 (VAR 47 predictor delay) and D2 (0.25 m/s landing below 0.15 m, xy freeze below 0.12 m). Neither has flown yet, so F1 is also the first flight of the D2 landing.

## Bring-up (drone disarmed on the pad)

1. **Firmware:** already flashed (0e6e01b6). Do not rebuild without flashing: an unflashed build makes 8081 read wrong addresses (friction B16).
2. **8081:** `python -m ground_station.service --port 8081`. Check status `arm 0` and motors about 3050 before anything else.
3. **Floor scan:** the phone moved 194 px on 2026-10-15, so scan again with the drone OFF the pad: `bash ground_station/lab/camera_truth.sh floor <name>`, id0 in most frames, then don't touch the phone.
4. **Fusion:** `CT_FLOOR=logs/video_truth/<name> bash ground_station/lab/camera_truth.sh fusion <flight> 3 --yaw-deg 94` (mode 2 for F2, F3). Pass: `g_ext_pos.n_ok` rising, `stale` 0, no "NO FIX SENT" overlay. MEASURED 2026-10-15 bench: n_ok 140 to 658, stale 0.
5. `camera_truth.sh stop <flight>` after each landing.

## Branches

| Event | Do |
|---|---|
| F2 or F3 aborts (tilt, geofence, `trip`) | Defaults are written back; keep the log. F4 uses only the loops whose flight finished |
| F3 not `recommended` | Re-fly F3 with `livetune ... seed=1`; still not: F4 keeps the default xy gains |
| F4 worse than F1 | That is a result: log it; reboot restores the defaults |
| F5 still shows the 2 Hz cycle | Re-fly with VAR 47 = 8, then 16 (edit `g_xyc_delay_ticks` in `lab_c_lqr.fly`) |
| "NO FIX SENT" during a flight | The camera is not correcting the drone: land, check the tracker, re-fly |
