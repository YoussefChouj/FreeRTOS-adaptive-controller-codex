## 6. The trajectory block, in the order you edit it

A `traj_p` struct has 16 fields. The fields you care about for the arm are `axis`, `move_s`, `ret_s`,
`hold_s`, `ramp_s`, `zz_amp_cm`, `zz_hz`, `circ_r_cm`, `circ_laps`. The other 7 (`profile`, `zz_shape`,
`f8_type`, `f8_a_cm`, `f8_laps`, `step_cm`, plus padding) you leave at the defaults unless you want
a non-smooth path. `profile = 1` (default) gives cosine ramps of `ramp_s` — easier on the arm than the
hard profile 0.

**The 16 fields, in struct order, with the values you set for the arm:**

| field | type | default | value for arm | range check |
|---|---|---|---|---|
| `profile` | uint | 1 | 1 (smooth) | 0 or 1 |
| `axis` | uint | 0 | 0 (x for zigzag), 0 (x for circle) | 0, 1, or 2 |
| `zz_shape` | uint | 0 | 0 (triangle) | 0 or 1 |
| `f8_type` | uint | 0 | 0 (don't use figure-8 on the arm) | 0 or 1 |
| `move_s` | float | 18 | **12** for zigzag, **15** for circle | ≥ 5, peak speed must be ≤ 80 cm/s |
| `ret_s` | float | 5 | 5 | 3 to 10 |
| `hold_s` | float | 2 | 2 | 0 to 5 |
| `ramp_s` | float | 3 | 2 (faster ramp, but still smooth) | 0.5 to `move_s`/4 |
| `step_cm` | float | 40 | 0 (don't use step on the arm) | ±50 hard, ±100 smooth, z ±40 |
| `zz_amp_cm` | float | 30 | **40** for 300 g, **30** for 450 g | up to 80, z up to 40 |
| `zz_hz` | float | 0.2 | **0.2** for 300 g, **0.15** for 450 g | up to 1.0 Hz |
| `circ_r_cm` | float | 40 | **30** for 300 g, **25** for 450 g | 10 to 80 |
| `circ_laps` | float | 1 | 1 (one full circle) | up to 3 |
| `f8_a_cm` | float | 50 | 0 (not used) | 10 to 80 |
| `f8_laps` | float | 1 | 0 (not used) | up to 3 |
| (padding) | | | | |

**The 25 s rule**: `move_s + ret_s + hold_s ≤ 25`. With our values: 12 + 5 + 2 = 19 (zigzag) or
15 + 5 + 2 = 22 (circle). Both under the cap. With `move_s = 18` (the default) you'd be at 25 exactly —
no headroom for `hold_s > 2`.

**The peak-speed rule**: the firmware refuses (status `0xEE`) any preset where the peak reference speed
exceeds 80 cm/s. With `zz_amp 40, zz_hz 0.2`: peak = 4 × 40 × 0.2 = **32 cm/s** (triangle) or
2π × 40 × 0.2 = **50 cm/s** (sine). With `zz_amp 30, zz_hz 0.15`: 4 × 30 × 0.15 = **18 cm/s** (triangle)
or 2π × 30 × 0.15 = **28 cm/s** (sine). Both well under 80. The circle peak is `2π × r / move_s`:
30 cm / 15 s = 6.3 rad/s, peak = 2π × 30 × 1 / 15 = **12.6 cm/s** for the 30 cm / 15 s case — also
plenty of headroom.

**The fence rule** (status `0xEF`): the shape must stay inside `|x| ≤ 1.3 m`, `|y| ≤ 1.7 m`,
`z ∈ [0.4, 1.4] m`. The circle's centre is at `x = traj_home_x - radius`, so a 30 cm circle started at
x = 0 has its centre at -30 cm, and the far edge of the circle reaches x = 0 — fine. A 30 cm circle
started at x = 0.5 m has its far edge at x = 0.8 m — also fine. The 80 cm default circle started at
x = 0 reaches x = -0.8 m — already half the fence. **Always start the circle at x ≥ 0.0 m** to be safe
with the 25-30 cm radius.

## 7. The pre-flight checklist (per flight)

1. Stream-log is running, terminal visible.
2. Load on the **right arm** (one motor out, 15-20 cm from body centre, same place every flight). Note
 which motor and the actual mass in grams; write it on the bench sheet. **0.3 kg and 0.45 kg only.**
3. Drone on the pad marker, props clear, RC on and in reach.
4. **Cold-boot state check:** `vp_active == 0`, `kp_active == 0`, `traj_active == 0`. If any is non-zero,
 power-cycle the drone and the bench.
5. **Set `kp_id = 5`**, pulse `kp_go = 1`, confirm `kp_active == 5`. (0xEE → not built with kp table; abort.)
6. **Set `vp_id`**, confirm `vp_active == vp_id` within 1 s. (0xEE → a field was refused; do not fly that
 row, see §10.)
7. **Edit `traj_p` fields** for the planned preset (see §6 table).
8. **Set `traj_id` to the number** (1, 2, 3, or 4 — *not* the character; the firmware accepts both but the
 status read-back tells you what the firmware actually saw).
9. **Set `traj_fence_off = 0`** (fence on) or `traj_fence_off = 1` (fence off). Default is 0. See §6 for the
 fence rules. `0xEF` on `traj_status` after `traj_go = 1` means the shape exceeded the fence; either widen
 the start or set `traj_fence_off = 1`.
10. Arm by RC. Throttle up. Take off to 0.8 m. Hover still for 3-5 s, hands off the sticks.
10. `traj_go = 1`. Watch `traj_status` go 1 (running), `traj_phase` 1→2→3, then `traj_status` 2 (done).
11. Land by RC. Disarm.

## 8. Splitting one CSV into 8 sessions (review prep)

The single `stream_log` CSV covers all 8 flights. Use the `traj_active` column: it is 0 during
hover/land, and equals `traj_id` while a preset is running. Split by the `traj_active` transitions:

```python
# One-off split script — run from the repo root after the arm session
import pandas as pd
df = pd.read_csv("logs/arm_session.slot0.csv")
# t_src_ms is the firmware's wall clock; gaps are landing
df["traj_active"] = df["traj_active"].fillna(0).astype(int)
# Each flight is bounded by traj_active == 0 → nonzero → 0 (or end of file)
flights = []
in_flight = False
start = 0
for i, row in df.iterrows():
    if row.traj_active != 0 and not in_flight:
        in_flight = True
        start = i
    elif row.traj_active == 0 and in_flight:
        in_flight = False
        flights.append((start, i))
# Save each flight as its own slot0 file under the name from the bench sheet
# (you match the order of flights to the names — keep the bench sheet in order)

    df.iloc[i0:i1].to_csv(f"logs/vofa/flight_{idx:02d}.slot0.csv", index=False)
```

## 10. Abort rules (the four)

Land at once if any of these:

1. The drone **tilts or drifts more than under PID** at the same load. PID is the baseline; the 3L rows
 must do better or at least match.
2. **`u_ad` (any axis) flat at its limit for > 1 s.** The `mrac_simplex.sat_ticks[axis]` watch variable
 counts 200 ms of saturation; a value above 40 means the saturation trip fired. You'll see `u_ad` on
 `mymotor.motor*` indirectly: the four motor values diverge. With ch8 off this is informational only;
 with ch8 on the saturation trips the simplex, fades `u_ad` to 0 over 100 ms, and freezes the weights.
3. **Motors near 100 %** (steady, not transient). Sim showed 16-20 % with the rope; arm loads will be
 higher. > 80 % steady = no thrust margin.
4. **Twitch / oscillation at 1-3 Hz.** Layer 1's `lam_ang` can wind up on a constant load; if the
 `e_int` watch variable grows past 0.4 (the `e_sat` clip is 0.5), the integral has saturated. Set
 `vp_id = 0` and land.

**RC ch10 is always the hard kill.** Move it and the motors stop, regardless of state.
