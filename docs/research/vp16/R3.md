# R3 — Adaptive outer loops, actuator/command saturation, and MRAC next to a PID

Scope: hedge an outer/position-loop adaptive element fed through a hard 15 deg lean clamp and an inner
attitude loop that is itself adaptive; motor/mixer saturation on attitude-Z; how MRAC augmentation is
added to an existing PID without the adaptive bias fighting the integrator; time-scale separation between a
100 Hz X/Y loop and a 200 Hz attitude loop; and first-flight safety practice. Every verbatim quote is from a
page (or extracted PDF) opened this session; the URLs are inline. Claims whose full text I could not open
this session are tagged **UNVERIFIED** with bibliographic data, per the evidence contract.

## Bottom line
A "cheap PCH": make the outer reference model see the *actually clampable* acceleration instead of the
unlimited command, and freeze/reduce gamma while any actuator or the lean clamp is saturated. That single
change removes the dominant error the 100 Hz X/Y adaptor would otherwise wrongly learn (the 15 deg clamp /
inner-loop lag), and it costs a few lines — no plant model needed. Fully decoupling the adaptive bias from
the PID integrator is a harder, separate problem; keeping each bump at ≤1% authority (as vp16 already does)
is the right first line of defence.

## Q1 · Adaptive element on the outer (position/velocity) loop; pseudo-control hedging (PCH)

**What PCH is, verbatim.** The concept was created for actuator saturation. From the safe-adaptive-
augmentation preprint (fixed-wing UAV; hedge applied to a learning-based augmentation):
> "pseudo control hedging (PCH) concept [27], originally designed to account for actuator saturation
>  effects" — arXiv 2609.29319, `https://arxiv.org/html/2609.29319v1`
> "we apply PCH to ensure that the RL-based adaptive augmentation does not compensate for interventions
>  introduced by the safety filter." — arXiv 2609.29319
The hedge is the achieved-minus-commanded pseudo-control; in that paper `v_h = g(x)(u_nom − u)` and the
reference model is modified to `ẋ_m = −K_bs x_m − v_h` so that "the model matching error dynamics become
invariant from the safety filter action" (ibid). Translating to a quadrotor: the reference model is slowed by
exactly the amount the plant did not move, so the adaptive error `e = x − x_m` no longer contains the 
artificial lag/saturation the plant could never follow.

**PCH on the path/outer loop, verbatim.** An ICAS 2008 trajectory-control paper (NDI on a TECS-style total-
energy path loop) places PCH in front of the path-loop reference model:
> "pseudo-control hedging signal which is added to [the path-angle reference model input]" — ICAS 2008
>  `http://icas.org/icas_archive/ICAS2008/PAPERS/496.PDF` (text extracted from the PDF; bracketed words glue
>  fragmentary extraction: the page read "…is added to" then "inputs the flight path angle reference m…"
>  two lines apart)
and its motivation is, verbatim fragments: "to account for saturated" / "to hide saturation" / "to avoid
unbounded weights" and "cascade with reference models and PCH" (ibid). "Hide saturation … avoid unbounded
weights" is exactly the failure mode we must stop: without hedging, the saturating nonlinearity shows up in
the tracking error and the adaptive parameters grow unboundedly trying to explain it.

**The Johnson & Kannan (2005) outer-loop claim** — that novel PCH use lets the outer adaptive loop run
without the inner attitude dynamics corrupting it, and that a pole-placement design relaxes the classical
time-scale-separation requirement — is reported in the PSU abstract and secondary summaries, but I could not
open the full text this session. **UNVERIFIED**:
- E. N. Johnson & S. K. Kannan, "Adaptive Trajectory Control for Autonomous Helicopters," *J: Guidance,
  Control & Dynamics* 28(3):524–538, 2005, DOI 10.2514/1.6271. PSU record (opened, abstract view):
  `https://pure.psu.edu/en/publications/adaptive-trajectory-control-for-autonomous-helicopters/`
- Companions: E. Johnson & A. Calise, "Limited-Authority Adaptive Flight Control for Reusable Launch
  Vehicles," *JGCD* 26(6):906–913, 2003 (PCH origin); S. K. Kannan, *Adaptive control of systems in cascade
  with saturation*, PhD thesis, Georgia Tech, 2005 (nested-saturation reference model for cascaded
  inner-outer adaptive loops) — both surfaced in search, neither full-text opened.

**What goes wrong without hedging in vp16.** The X/Y adaptor adds to a velocity-loop acceleration command
that is hard-clamped at 15 deg lean. Whenever the demanded accel wants more than 15 deg, the *clamp* (not the
plant's true fault) truncates the command; the velocity loop does not reach its reference, so `e` grows, and
the MRAC law `Theta_dot = gamma(−s·Phi/(1+‖Phi‖²) − sigma·Theta)` (per the R3 brief, `API/mrac.c`) raises
bumps against an error the adaptation can never fix while the clamp is on. The adaptive parameters learn the
clamp and the inner-loop lag instead of the real unmodelled torque — reproducing vp13's phase-wrong pitch
`u_ad`. The readthedocs implementation states the staying-out-of-trouble rule outright:
> "the gap ν_des − ω̇_meas is fed back to the reference models so they freeze under saturation"
> "PCH uses the acceleration demand from the previous tick." — Tensor Aerospace AIDI docs,
>  `https://tensoraerospace.readthedocs.io/en/stable/agent/aidi/`
Its hedge is multivariate ("Hedge vector ν_h of shape (n_y,)"), i.e. freezing is per-axis — as vp16's per-axis
axes need.

**Cheapest fix for vp16, ranked.** 
1. *Minimal position-loop PCH (recommended, cheapest and most robust):* drive the X/Y first-order reference
   model with the *actually permitted* command, i.e. clamp the demand at 15 deg *before* it enters the
   reference model (convert the accel clamp to the equivalent max convex gain / accel bound). Then `x_m` never
   asks for what the clamp forbids and `e` stays clean — the "reference model rate command limiter" idea from
   ICAS 2008 (ibid). No plant model, ~a few lines.
2. *Freeze/reduce gamma while saturated:* halt the weight update whenever the lean clamp or any per-bump
   limit is active (the readthedocs "freeze under saturation" / "per-axis freeze counter", ibid). Cheap, but
   it kills learning during the very transients that need it — use only to bound the damage of a clamp.
3. *Anti-windup on Theta:* the sigma=0.01 damping and per-weight projection already bound growth; an explicit
   integrator-state clamp on `Theta` adds robustness but is largely subsumed by the projection vp16 already has.
Recommend 1 + 2 together; keep 3 only if 1 is too intrusive to implement quickly.

## Q2 · Motor saturation and mixer limits while adapting on attitude and Z
Same mechanism, one layer down. If a motor or the mixer limit truncates commanded torque (pitch/roll/yaw)
or thrust (Z) while the adaptive law is running, the attitude/Z `u_ad` sees an unreachable reference and
learns the saturation. The same two braces apply: (a) the reference model must be slowed by the hedge
`v_h = u_achieved − u_commanded` (arXiv 2609.29319 definition, above), and (b) freeze-on-saturation per axis
(readthedocs AIDI quote, above). For the Z/collective channel specifically, motor saturation during fast
vertical commands is the classic case the PCH hedge was built for; the ICAS source's "avoid unbounded
weights" rationale covers it verbatim (Q1). A flier worth keeping: the PCH hedge for Z should be computed from
the *achieved* thrust command as seen *after* the mixer, and the reference model should be the same first-order
model used for attitude so the time constant is consistent. No additional verified flight-test source for
Z-collective saturation under MRAC was opened this session; treat that specific guidance as (own estimate)
built on the Q1 mechanism.

## Q3 · MRAC augmentation of an existing PID; reference-model choice; integrator conflict; CRM
**Augmentation sits in parallel and must be near-zero when the plant is nominal.** Verbatim (missile
autopilot, learning augmentation layered on fixed-gain autopilot):
> "augmenting the classical autopilot's fixed-gain controllers with a learning-based controller"
> "we augment the fixed-gain controllers in the three-loop autopilot with adaptive controllers in parallel"
> "the performance of the A-TLA is similar to that of the F-TLA [when nominally tuned]"
 — arXiv 2509.07748, `https://arxiv.org/html/2509.07748v1`
This is the vp16 target: the augmentation sum `u = u_PID + u_ad` should leave PID behaviour unchanged at
nominal and act only off-nominal. vp16's per-axis 15%/1% authority limits are exactly the "limited authority"
philosophy of Johnson & Calise (UNVERIFIED, bibliographic above).

**Reference-model choice.** The MRAC reference model sets the target the plant is driven toward; if it is
faster than the baseline closed loop can deliver, the adaptor forever chases an unreachable ideal. The
closed-loop-reference-model (CRM) literature is the formal answer to "how to pick it":
> "x˙m = Am xm + Br − L(y − ym), ym = CT xm" and "This controller makes use of a closed-loop reference model
>  as an observer" — arXiv 1410.1944, `https://arxiv.org/html/1410.1944v1`
> "guaranteed transient properties by using a closed-loop architecture for reference models" — ibid
CRM feeds a copy of the tracking error back into the reference model (observer-like `L` term), so the
reference follows the *actual achievable* closed-loop rather than an ideal that ignores saturation/lag — this
directly addresses "don't make the reference model ask for more than the PID inner loop can give."
> "Gibson et al. (2013) derived a novel MRAC scheme (which they named Closed-loop Reference Model, CRM)"
 — arXiv 2512.14175, `https://arxiv.org/html/2512.14175v2`
Primary CRM papers (T. Gibson, A. Annaswamy, E. Lavretsky, "On Adaptive Control with Closed-Loop Reference
Models: Transients, Oscillations, and Peaking," *IEEE Access* 1:703–717, 2013; and the 2015 *IEEE TAC*
output-feedback follow-up, arXiv 1410.1944 above) were not opened in full this session — **UNVERIFIED**
bibliographically, but the mechanism is captured by the quotes above.

**Keeping the adaptive bias from fighting the PID integrator.** Two distinct problems:
- *Bias vs integrator trim:* vp13 already shows `u_ad` carrying 45–60% of static trim with the PID integrator
  taking the rest — a tug-of-war where both try to hold the same value. The 2509 quote ("similar to that of
  the F-TLA") is the target: the adaptive bias should be small when the PID can already trim it.
- *Noise-injected bias in the law:* the adaptive law is not immune to measurement noise appearing as a bias;
  verbatim: "the measurement noise variance R presents itself as a bias term, causing growth in k̂ even when
  x = x̂" — arXiv 2512.14175 (KalMRACO). vp16's sigma + projection and the `1+‖Phi‖²` normalisation all
  counteract this; the tanh `e_sat` already desaturates the error.

## Q4 · Time-scale separation between 100 Hz X/Y and 200 Hz attitude adaptive loops
Classical practice is that each outer loop runs at a fraction of the inner-loop bandwidth, and Johnson &
Kannan's 2005 point is that PCH plus pole-placement relax the classic separation requirement (UNVERIFIED,
bibliographic Q1). With separate per-axis parameters the two adaptors only couple through the plant
(outer X/Y demand feeds the attitude reference), so the real risk is the *outer* adaptor modelling the
*inner* loop's lag. The hedge fixes it: once the outer reference model is kept at or below what the inner
loop + clamp can actually deliver (Q1 fix 1), frequency separation matters less. Rule of thumb used here
**(own estimate)**: make the outer X/Y reference-model time constant clearly slower than the attitude
closed-loop time constant (a factor ~2–4), and let the per-axis gamma fill time `T` (vp16 = 3 s) dominate
the inner-loop settling time so the two adaptors do not race. No additional flight test quantifying a
two-adaptive-loop rate split was opened this session — **UNVERIFIED** for the specific 100/200 Hz numbers;
the separation principle itself is grounded in Q1's sources.

## Q5 · First-flight safety: masks, freeze, reset-on-arm, gamma ramp, shadow mode
The universally documented practice is *enable adaptation only in the air and off-nominal, on top of a
working baseline*. From the NASA GTM / AirSTAR programme (search-confirmed descriptions; **UNVERIFIED**
full text):
- AirSTAR GTM testbed: a safety pilot (conventional RC) flies takeoff/landing and hands over in the air;
  research/adaptive control laws are engaged after handover, mid-flight. Sources: "AirSTAR: A UAV Platform…"
  `https://ntrs.nasa.gov/api/citations/20060022136/downloads/20060022136.pdf`; the L1 test was engaged at
  ~485.9 s in flight and flew ~12.5 min continuously. **UNVERIFIED** (could not decode the PDF text).
- ACTS architecture = a nominal *non-adaptive* controller plus adaptive augmentation; "Verification and
  Tuning of an Adaptive Controller for an Unmanned Air Vehicle," NASA NTRS 20100031105, and "Design of a
  Model Reference Adaptive Controller for an Unmanned Air Vehicle," NASA NTRS 20100031112. **UNVERIFIED**
  (PDFs downloaded but FlateDecode/object streams would not decode with the available tooling).
- F/A-18-class fast-adaptation damping ("opti-like modification", OCM): "An Optimal Control Modification to
  Model-Reference Adaptive Control for Fast Adaptation," NASA NTRS 20090026330. **UNVERIFIED**.

The verifiable principle to build on: an augmentation that is *worth having* is also one you must be able to
switch off cleanly, and it must not compensate for interventions the safety layer already makes — which is
the entire point of PCH in 2609.29319 (Q1 quote). Recommended vp16 ladder (**(own estimate)**, shaped by the
above):
1. *Shadow mode first:* run the full adaptive computation every tick, log `u_ad` and `Theta`, but inject 0.
   Confirm `u_ad` stays ≤1–15% authority and stays quiet when PID alone is good.
2. *Reset on arm & freeze on ground:* zero `Theta` on arming; hold the update dead until the vehicle leaves a
   ground/armed-hold condition (mirrors the pilot-handover practice above).
3. *Gamma ramp / low fill time first:* start with a reduced gamma (longer `T`) and raise it only after shadow
   passes are clean. Avoid baseline-fast gamma on flight 1.
4. *Per-axis enable masks + freeze under saturation* (Q1/Q3), so a bad axis can be dropped without killing
   the rest, and any clamp/mixer limit pauses that axis's learning (AIDI freeze quote, Q1).

## Implications for other variants
- **Structured S6/S10 features:** the bias row (`phi=1`) is the static-trim knob that most directly collides
  with the PID integrator — cap it at the smallest value that trims, and confirm it does not grow in shadow
  mode (Q3). S6/S10 features should be gated by the same saturation-freeze logic so a malformed feature does
  not accumulate during a clamp.
- **RBF24T grid:** per-bump 1% limits are the correct "limited authority" reading of Johnson & Calise
  (UNVERIFIED, Q1); the densest-near-hover centres are safest because most flight time sits near hover where
  `u_ad` should stay tiny; keep the fixed `T=3 s` fill time (it already sets the adaptation rate) and ramp it
  up only after shadow passes (Q5).
- **L1 filter (omega_u=4–20 rad/s):** the low-pass on `u_ad` is already hedging high-frequency chatter; the
  missing piece is *not* the filter but the reference model's command source — add the clamp-aware command so
  the 4–20 rad/s filter low-passes a signal that is not chasing the lean clamp (Q1). Freeze-on-saturation
  below the filter is complementary (Q2).
