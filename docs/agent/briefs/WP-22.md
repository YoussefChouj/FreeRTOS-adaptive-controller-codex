# WP-22 brief (CEO -> Manager), 2026-10-03. Survive a reflash without restarting 8081, plus a stale-state audit.

Base: `main` (5472805 or later). Ground-station code and tests only.
No Keil build, no flash, no 8081, no probe, no firmware (`.c`/`.h`), do not touch `OBJ/` or `USER/`.

## Why

The operator reports that after every flash the running 8081 service has to be restarted, or streaming and/or
logging break. Workflow B (fly campaigns with auto logging) makes this worse: a campaign that starts on a stale
service records empty or wrong data.

Known root cause, from `docs/agent/HANDOFF.md` ("RECORDER 0-ROW ROOT CAUSE"):
- 8081 kept running across the reflash.
- The new axf moved the RAM variables by 12 B.
- The bridge re-registered the default slot 0/2 echoes with a stale name table ("0 named, N unnamed"), so positional
  names never matched the recorder's var names and every row was dropped. Slots 1/3 (names in the preset) were fine.

Code anchors:
- `ground_station/comm/wifi_bridge.py` `subscribe_slot` (~1058) and schema registration (~2100-2200, the S15 lines).
- `ground_station/service/streams.py` `_ResolverCache` (~110) and `api.py` `_own_symbol_resolver` (~576): two
  separate mtime caches of the same ELF.
- The resubscribe watchdog: `bridge._resubscribe_fn` / `_resubscribe_layout` in `service/__main__.py` ~125-201,
  `api.py` ~289-305, `streams.py` ~672.
- `ground_station/service/campaign_live.py` `live_capture_hooks`: workflow B's per-flight capture.

## Changes

A. **Reflash detection.** The service notices a new firmware without a restart, from the axf changing on disk
   (mtime + size or hash of `vofa_studio.core.ELF`) and/or a firmware identity or FC reboot seen on the link. On
   detection:
   - reload ONE shared symbol resolver (replace the two caches);
   - rebuild every name table;
   - re-apply the active layout or preset on all slots;
   - log one line saying what was re-applied.

B. **Names from the request.** A schema reply is named from the names the GS requested for that slot (request ->
   reply match), never from a positional fallback against an old table.

C. **Visible fault, no silent drops.**
   - An unnamed range after the re-apply, or a recorder that drops every row, becomes a visible fault: a field in
     `get_state` plus the existing dashboard fault path.
   - `live_capture_hooks` begin raises `RuntimeError("stream not named: ...")` in that case, so the workflow B
     runner refuses to fly unlogged (`test_runner_refuses_to_fly_unlogged` already covers the refusal path).

D. **Stale-state audit (report only, plus fixes that are under ~20 lines each).** Table every piece of state that
   8081 or the agent tooling sets once and that goes stale after each of these events:
   1. a reflash;
   2. an FC reboot or power cycle;
   3. an 8081 restart;
   4. GS code changing on disk.

   For each row: what goes stale, the symptom, and the fix (auto-heal / preflight check / by design, document).

   Known rows to include:
   - `allow_agent_arm` resets on 8081 start: by design (safety), keep it.
   - The dashboard MCP server keeps old tools until the Claude session restarts.
   - 8081 holds the axf open during a flash (memory note "8081 locks axf"); check what `flashtool/rebuild_and_flash.py`
     does about it.
   - The preset replay after an FC reboot.
