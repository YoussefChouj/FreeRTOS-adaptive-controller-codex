Measured facts (that report, f17 logs): `g_thrust_est.empirical[]` is constant 12.8-12.9 N (motor CCR 2000-4000 fed
to a 1100-2000 us table); `imu_total` is constant 9.697 N because `imu_data.a_acc` is never written (only reader

hover sum omega^2 is constant within 0.4% across 6 flights; k_T = 6.80e-6 at 0.9885 kg (mass unverified);
ch3 is faulty (13-42% outliers); ch0/ch2 are the CCW pair (M3/M4), ch1/ch3 the CW pair, corners unresolved.

CEO decisions:
1. `API/thrust_estimators.c/.h`: first prove the CCR unit from `BSP/pwm.c` (timer clock, prescaler, period) and
   quote those lines in the report. Then express the lookup table in the motor's own units (or convert once, not
   both). One calibrated k_T `#define` with a WHY comment naming the mass it assumes. Add `sum_w2`, `mass_hat`
   (= k_T sum_w2 / (g + a_z)), and `cw_share` (CW pair omega^2 share), each low-passed with a 1 s time constant at
   the call rate. Keep it telemetry only: nothing may feed control.
2. Replace the `imu_data.a_acc[_Z]` argument at `TASK/StabilizerTask.c:1167` with the gravity-removed vertical
   acceleration the task already computes (see `Lin_Acc_Z_body`, ~533). Check its units and frame and say so; do
   not write `imu_data.a_acc` (WP-14 decides that).
3. `BSP/rpm.c` ~236-246: replace the 4-revolution mean with a median of the last 5 periods, so one missed or extra
   edge cannot move the reading. Keep the ISR cost bounded (insertion sort of 5, no division in the ISR if the
   current code avoids it).
4. No per-corner torque in firmware tonight (the corner map is unknown). Do it in analysis instead:
   `hover_thrust_id(log, mass_kg, motor_of_ch, arm_m=0.1414)` in `ground_station/analysis/rpm_signals.py`: hover
   k_T, mass, CW/CCW share, and roll/pitch torque for a given channel-to-corner map, with ch3 outliers masked; a
   `--compare loaded unloaded` mode giving the payload torque from the difference. CLI
   `python -m ground_station.analysis.rpm_signals --logs logs/vofa` prints the k_T table for the f17 flights.
5. C for Keil ARMCC V5.06: declarations at block top, no VLAs, no C99-only constructs. Tables follow
   `docs/firmware-table-pattern.md` if you add any.
