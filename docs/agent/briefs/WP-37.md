## Why
The operator wants every firmware module as maintainable and readable (for them and for agents) as `API/pid.c`: tunables in aligned `*_ROW`
tables, named constants, short functions, one place per concept. Telemetry uses the subscribe system (`API/subscribe.c`, `API/subscribe.h`,
`SUBSCRIBE_MAX_SLOTS`), which streams variables by symbol/address: the key flight variables should sit together in memory so a slot covers
a related group cheaply, and the operator asks whether more than 4 slots fit with minimal overhead.

## Changes (all behaviour-preserving; one commit per module; `bash tools/check.sh` and `python API/tests/run_mrac_equiv.py` green after each)
A. Refactor, in order of value: `TASK/StabilizerTask.c`, `API/controller.c`, `TASK/send_data.c` (split command decode into a table of
   handlers if it is a long switch), `API/mrac.c`, the estimators (`API/ekf_of.c`, `API/thrust_estimators.c`), then the rest as time allows.
   Per module: file header (purpose, rate, inputs/outputs, owner task), tunables as `*_ROW` tables, magic numbers named, long functions split,
   dead code removed only when provably unused (grep + host build). No timing, order-of-operations or numeric change; where a refactor would
   change floating-point order, leave it and note it. Put the remaining modules in the report as a list.
B. Memory layout for telemetry: read how subscribe.c samples a slot (per variable address+size, or a block?). Group the key flight state
   (attitude, rates, setpoints, motor outputs, MRAC/adaptive terms, estimator outputs, battery/thrust) into a few named structs placed
   together, so one slot can stream a related block. Keep every symbol the ground station uses resolvable: update the symbol map / capability
   manifest generator and `ground_station/platform` tests in the same commit (`test_command_symbol_map.py`, `test_capability_manifest.py`).
C. More slots: measure RAM per slot (`sizeof(Subscribe_Stream_t)` on the host build), op count per tick per slot, and the UART budget (baud,
   frame sizes, the existing 10 ms slot comment at `TASK/send_data.c:1093`). Recommend a slot count; if 8 (or the recommended N) costs
   < 1 KB RAM and keeps the bandwidth guard, implement it behind one `#define` and update the ground-station side to accept N slots, with tests.
D. `docs/firmware-structure.md` (<= 100 lines): module map (task, rate, files, key structs, tunable tables), how to add a tunable, how to add a
   telemetry group, the slot budget.
