## Why
Every lab session loses time switching experiments: the xy controller is one VAR, the MRAC variant (`vp_id`) and limit mode
are Keil-watch only, and the xy MRAC reference model is tuned to PID only, so with LQR/MPC/ADRC it fights the controller.
Goal: one `.fly` line `exp <name>` selects a whole, consistent experiment on the ground, read back before arming.

## Scope
1. Firmware row table `s_exp[]` in `TASK/StabilizerTask.c`, aligned `EXP_ROW(...)` macros in the `s_kp`/`s_stage` style with
   a `tools/row_meta.py` legend. Columns (0xFF / -1 / NaN = "keep current", so rows compose with later `set` lines):
   name token (bare identifier, unused by C, parsed by ground), `xy` (g_xy_ctrl_kind 0-3), `kp` (kp_id row: inject axis mask),
   `vp` (vp_id row, p/r/yaw variant incl. 3L-v2 rows 16-19), `lim` (lim_mode 0-2), `mdec` (g_imu_mahony_yaw_decouple 0/1),
   `xyrm` (row of a new `s_xyrm[]`, -1 = auto = the row for this `xy` kind), `layer` (reserved for WP-C, 0 = off).
2. No-fight xy reference model: new table `s_xyrm[]`, `XYRM_ROW(ref_type, bw, crm_ell, g)` applied to mrac_config_x and _y,
   one row per xy kind. PID row = today's values (bw 2.0 measured). ADRC/LQR/MPC rows: fit each kind's closed loop with the
   same method (first-order fit of FB to Des) in a host SIL of the xy loop (double integrator + attitude lag + the VAR 47
   delay; reuse an existing xy/MRAC SIL if present) and mark every such number `PROPOSED (SIL fit)` in its comment.
3. `exp_id` (boot 0xFF = none, nothing changes) and `exp_active` (0xFF none, 0xEE refused). `Exp_Poll(state)`: ground only
   (`Keil_OnGround`), on change, runs BEFORE the existing kp/vp/lim/stage pollers so they apply what it wrote. An in-air
   request waits for the ground (same rule as kp_id). Bad id -> 0xEE, nothing written. ch8 (`output_injection_on`) stays the
   only injection master: an exp row never writes it.
4. VAR_WRITE allowlist rows (ids 50+): `exp_id`, `vp_id`, `lim_mode`, `g_imu_mahony_yaw_decouple`, ranges from the tables.
5. Readback: put `exp_active` (and, if room, `vp_active`, `kp_active`, `lim_active`) in telemetry so the ground can confirm.
   Prefer a spare/reserved byte in an existing frame (`TASK/send_data.c`, `ground_station/platform/firmware_contract.py`);
   if none exists, say so and pick the least invasive option. Report the exact field.
6. Ground: `exp <name>` line in `fly_file.py` -> `set exp_id=N`, names parsed from the `EXP_ROW` lines in the C source
   (single source of truth, like wfb_var parses VAR_WRITE_ROW). The runner waits (<= 2 s) for `exp_active == N` before the
   next `set` and before arming; mismatch or 0xEE -> refuse takeoff with a clear message. `./fly --list-exp` prints the table.
7. Rows to ship (all PROPOSED): `pid`, `adrc`, `lqr`, `mpc` (kp 7, vp 0, lim 0, mdec 1, xyrm auto) and the same four with
   the 3L-v2 row used by `ground_station/service/campaigns/rope570_3l.yaml` (`pid_3l`, ..., `mpc_3l`). One example
   `ground_station/service/campaigns/lab_e_exp_matrix.fly` flying a hover + figure-8 per `*_3l` row.
