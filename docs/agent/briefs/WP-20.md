## Why

Flight `flight_test_hover_2` held position within ±1 cm in the air. It still landed about 20 cm (x) / 30 cm (y) from
where it took off, and optical flow (OF) saw only 5.1 / -2.9 cm of that. The handheld test `of_scale_test_1`
(disarmed, `g_of_handheld_test=1`, height 0.7-0.9 m) showed two faults. Notes: `.claude_state.md`, last two entries.

1. **Scale.** Eight 50 cm tape moves read 31-45 cm (most 37-44) in `locxPID.FB` / `locyPID.FB`. OF reads about 80%
   of the real distance.
2. **Vertical-motion coupling.** Pure vertical hand motion with no sideways motion still moved the position:
   - lift 0 -> 0.9 m (t 7-8.5 s): +3.5 / -7.5 cm;
   - lower 0.6 -> 0.4 m (t 69-70.5 s): -2.7 / +7.0 cm;
   - slow lower 0.4 -> 0.1 m (t 73-79 s): -5.3 / +4.2 cm.

   On the ground at the end, `of2_dx_fix` = `of2_dy_fix` = -1 constantly.

Logs are in `logs/vofa/`: `of_scale_test_1.*` and `flight_test_hover_2.*` (meta.json + slot0..3, `t_src_ms` in ms).
The two files use different slot layouts, so read each meta.json for the variable list.
- Slot3 (OF, `of_quality`, `s_of_bias_*`, `g_of_hold_active`) and slot0 (yaw, `ARM_Status`, `Z_posPID.FB`) match.
- In `of_scale_test_1`:
  - slot1 (50 Hz) has the loc/locs PIDs and `of2_*_fix`;
  - slot2 (50 Hz) has `Z_ratePID.FB`.
- `flight_test_hover_2` has `flight_phase` in slot1.

## Firmware changes (`TASK/StabilizerTask.c`)

Code anchors:
- the OF position integration and `pos_integrate` gate are around lines 537-592 (`of_dx_deb` at ~580);
- the velocity loop FB, `of2_*_fix - s_of_bias_*`, is in `case_Update_v_loc_Des` (~1440-1466);
- `ComputePID_Gated` is used at ~1140-1153.

Follow `docs/firmware-table-pattern.md` for the new tunables (aligned `*_ROW` / define table).

A. **`OF_VEL_SCALE 1.25f`.** Apply it to the debiased OF velocity, `(of2_*_fix - s_of_bias_*) * OF_VEL_SCALE`.
   - Use it in one helper, so that position integration and velocity-loop FB use the identical scaled value.
   - The handheld test path must use it too, so the operator's second handheld test measures the new scale.
   - If the OF EKF (`s_ekf_of`, `API/ekf_of.c`) consumes the flow, either apply the same scale there or explain in
     the report why not.

B. **Vertical gate.** Add `u8 g_of_vgate` (1 = gated, global, so the dashboard can log it).
   - Gated when:
     - height < `OF_GATE_MIN_ALT_M 0.40f`;
     - or |climb rate| > `OF_GATE_VZ_CMS 20.0f`;
     - or the height reading is invalid (`of_alt_cm` == 0xFFFFFFFF).

     Pick the height and climb-rate signals the firmware already trusts (`Z_posPID.FB`, `Z_ratePID.FB` or the
     altitude estimator) and state the units in the report.
   - Add hysteresis or a minimum gate time of about 0.3 s so it doesn't chatter in hover.
   - While gated:
     - do not integrate OF position, in flight or in the handheld test;
     - the horizontal position and velocity loops command zero tilt (level plus the existing attitude trim);
     - integrators are frozen, not reset;
     - `locxPID.Des` / `locyPID.Des` are not re-synced.
   - When ungated: resume holding the same Des.

C. **Landing pause.** Do this only if the firmware has an automatic landing descent; check `API/flight_fsm.*` and the
   sink-bias logic at ~1408.
   - If descent is pilot-throttle only, add nothing and say so in the report.
   - If it is automatic: hold altitude at 0.40 m until |pos err| < 3 cm and |v| < 5 cm/s (timeout 3 s), then descend
     with the gate active.

D. **Preset.** Add `g_of_vgate` and `Ctrler.Z_ratePID.FB` to the 20 Hz slot of
   `ground_station/vofa_studio/presets/position_hold_of.json`.

## Offline replay (proves A+B on the real logs)

Add `ground_station/research/of_gate_replay.py`, runnable as
`python -m ground_station.research.of_gate_replay --logs logs/vofa`. It re-integrates the OF position from the logged
`of2_*_fix`, `s_of_bias_*`, yaw, height and climb rate, using the same constants and gate logic as the firmware.
It prints:
1. `of_scale_test_1`: for each of the 8 horizontal moves, the scaled displacement. Mean must be 47-53 cm.
2. `of_scale_test_1`: the gated position change over the vertical segments t 7-8.5 s and 69-79 s. Must be <= 1.0 cm
   per axis.
3. `flight_test_hover_2`: the share of `g_of_hold_active==1` airborne time that would be gated. Must be <= 10%
   outside the first 3 s after takeoff and the landing descent.

Add one pytest on a small synthetic CSV.
