# WP-22 report: survive a reflash without restarting 8081 (CEO inline, 2026-10-03)

Status: DONE (code + tests). Not yet proven on the bench: needs one reflash with 8081 left running.

## What was broken

After a reflash, the running 8081 kept the old firmware's picture of memory in four places:

1. Cached 0x21 request bytes. The slot watchdog re-sent them byte for byte, so the FC streamed the old addresses.
   After a reflash that means the wrong memory under the right names.
2. The bridge names a 0x08 reply by matching (address, size) to the request. After the FC reboots, its boot-default
   echoes and its replies to stale requests match nothing. They register as unnamed, and the recorder drops
   unnamed samples, so logs came out empty.
3. Three separate symbol-resolver caches (bridge presets, `/api` symbols, streams), each reloaded on its own schedule.
4. `SymbolResolver` held `OBJ/JX_FLY.axf` open, so the Windows file lock blocked `rebuild_and_flash` (it deletes the
   axf before linking).

## Fix (diff summary)

| File | Change |
|---|---|
| `livewatch/symbols.py` | Reads the ELF into memory (`io.BytesIO`), so no lock is held. Adds `firmware_key()` (mtime_ns, size). Adds `shared_resolver()`: one process-wide cache that reloads when the key changes. |
| `service/api.py`, `service/streams.py` | Use `shared_resolver` (one cache instead of three). |
| `comm/wifi_bridge.py` | Stores each slot's request by name with a rebuild closure. Heal = re-subscribe by name against the current axf, on a thread, at most once per 5 s and 3 times per slot until a fully named reply arrives. The watchdog and `resend_slot` rebuild by name instead of re-sending stale bytes. A slot the GS stopped that streams again after a reboot gets its stop re-sent. Adds `stream_naming_status()`. |
| `service/campaign_live.py` | `wait_streams_named()`: campaign begin waits up to 3 s, then raises `stream not named: slot N: ...`. The runner refuses to fly without logs. |
| `service/core.py`, `agent.py`, `api.py` | New `stream_naming_faults` field: on `ServiceState`, `/api/view-model` and `/api/agent/state` (the MCP `get_state`). |

**Detection signal.** The heal fires on FC evidence only: an unnamed 0x08, or a silent slot whose request was built
against an older axf key. A new axf on disk alone only logs one line. Keil writes the axf before the flash, so the
old firmware is still running at that point, and re-subscribing early would request addresses the running FC does
not have.

## Audit: friction after reflash / FC reboot / 8081 restart / GS code change

| Event | Stale state | Symptom | Now |
|---|---|---|---|
| Rebuild | 8081 holds the axf open | Flash/link fails with a file lock | Fixed: ELF read into memory |
| Reflash | 3 resolver caches | Panels disagree on names and addresses | Fixed: one `shared_resolver`, keyed by mtime+size |
| Reflash | Cached request bytes re-sent by the watchdog | Wrong memory streamed under the right names | Fixed: rebuilt by name when the key is stale |
| Reflash / FC reboot | Boot-default echo replaces the GS layout | Unnamed slot, empty log | Fixed: heal by name (≤3 tries, visible fault) |
| FC reboot | Slot the GS stopped is back on (boot default) | Link budget eaten | Fixed: stop re-sent |
| FC reboot | Preset layout lost | Panels blank | Already handled: `_resubscribe_fn` replay |
| Any | Unnamed stream at campaign start | Flight flown without a log | Fixed: begin refuses with "stream not named" |
| 8081 restart | `allow_agent_arm` resets to off | Agent cannot arm | By design: the operator sets it; Q4 preflight row |
| 8081 restart | Claude session's dashboard MCP tools point at the old process | MCP calls fail until the session restarts | Documented: the skill falls back to the panel Go button |
| GS code change | Python modules loaded at start | New GS code not live | Documented: restart 8081 (only for GS code, never for firmware) |

## Risks

- The heal re-subscribes at most 3 times per slot. A slot that is still unnamed after that stays faulted and visible,
  and blocks campaigns until the operator re-applies the layout.
- A variable renamed or removed in the new firmware is dropped from the request and logged. It is not resolved
  silently.
- Not yet run against the real FC. Proof step: reflash with 8081 running, then check `get_state.stream_naming_faults == {}`
  and that a recording has rows.
