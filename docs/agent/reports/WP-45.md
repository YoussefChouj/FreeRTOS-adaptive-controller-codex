# WP-45 report: a Keil preset runs from a WiFi (WFB) hover, done inline by the CEO, 2026-10-14

Status: DONE (source + glue host test). NOT done: Keil build, reflash, on-drone test (next lab, with WP-44).

## Why
The operator wants `fly` to take off, run presets (traj_go), and land with no RC between them. Under a WFB HOVER the
glue sends the hover setpoint every 5 ms tick (`wfb_apply` sets `TWC.execute = 1`), so `Traj_Start` refused with
`0xE1` busy. The ch7 fly-up without WFB is no way out: by code reading (UNVERIFIED on the drone),
`AutoflyTask_PathArbitrate` clears `TWC.execute` once RC authority is 0, and `Thr_GsTakeoff` latches the throttle only
during a GS flight, so the low throttle stick owns z and the fly-up probably does not climb. Decision (operator: "you
have the firmware figure it out"): keep WFB takeoff / hover / land, and let the hover hand the point to a preset.

## Rule
- `API/wfb_glue.c`: HOVER sends no setpoint while `in->preset_active` (new `wfb_glue_in_t` field). Prim state stays
  HOVER, so the heartbeat watchdog, fence LAND_IN_PLACE, tilt kill, 120 s cap and GS land still run. CLIMB, TRAJ,
  RETURN and SETTLE are unchanged. A pilot stick during a preset is still a takeover.
- `TASK/StabilizerTask.c`: `in.preset_active = traj_active` (extern from AutoflyTask.c).
- `TASK/AutoflyTask.c`: `Traj_TwcBusy()` = `TWC.execute` set by anything but a GS flight in HOVER. `Traj_Start` and the
  `Traj_Tick` abort test use it, and both clear `TWC.execute` under the critical section (covers the one tick before
  the glue sees `traj_active`). `AutoflyTask_PathArbitrate` untouched.
- The preset ends at traj_home = the hover point, `traj_active` returns to 0, and the glue holds that same point again.
  A GS land during a preset: LANDING, then `Traj_Tick` ends the preset with status 3 (aborted).
- RC authority: the WFB takeoff goes through the ch7 fly-up, which releases it (StabilizerTask.c l.2255), so in
  HOVER only `TWC.execute` made `Traj_Start` busy. During the preset the authority is 1 and `Thr_StickActive()` is 0
  (GS throttle latch), the same z hold as a preset after an RC take-off. `Traj_End` gives the authority back.
- `sim/sil/csrc/sil_server.c`: `gi.preset_active = 0` (its input struct is not zero-initialised).
