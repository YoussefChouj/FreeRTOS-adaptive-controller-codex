## What changed
- `comm/wifi_bridge.py:433` `_check_slot_watchdog`: a slot silent for max(3 s, 5 periods) while other frames
  arrive is marked "stale" (:443) and its saved request is re-sent, at most every 5 s (:426, :445).
- `comm/wifi_bridge.py:476` `_check_resubscribe`: runs the watchdog on every non-subscribe frame, then re-sends the
  whole layout when no subscribe data has come for 3 s (an FC reboot), at most every 10 s.
- Stream requests are coalesced before `build_stream_request`; each element keeps its own name.
- `service/streams.py:234` `check_faults`: the logger marks a slot "fault" in its meta (:304) when it got no rows.
- `service/streams.py:683` `preflight_check`: counts frames per configured slot over 2 s and needs 80% of the
  rate. A silent slot is re-sent once and re-checked for another 2 s. `/api/streams/log/start` (:927) refuses
  with 409 unless `skip_preflight`.
- CEO fix, `service/streams.py:686`: the preflight returns ok when `service.source == "sim"`. The simulator has
  no radio link, and without the skip every sim campaign stalled at arming (3 new test failures).
- `analysis/flightlab/loaders/vofa.py:134-151`: masks the `of_alt_cm` sentinel 4294967295 and >5x-median
  spikes to NaN, and records the counts in `meta["masked"]`.

## Where the arm gate is wired
- `service/campaign_api.py:106` `arm_allowed`: agent permission first, then the stream preflight; a failure
  stores the reason in `arm_refusal`.
- Called once, at `campaign_runner.py:201`, before arming. It blocks for 2 s (4 s when it re-sends a slot).

## Risks
- Fail-open: with no bridge, no `_stream_stats` or no configured slot, the preflight returns ok; with no
  check at all, `arm_allowed` returns True. Arming is never blocked by missing plumbing, only by a silent slot.
- The 80% threshold uses the requested rate. The WP-13 budget note quotes slot 1 at 16 of 20 Hz (not
  re-measured tonight); that is exactly 80%, so a slightly slower link would refuse arming. Check on the
  first flight's dashboard before blaming the drone.
- The watchdog re-sends from the RX thread with `sendto`; a dead socket only prints a warning.
- Not run on hardware: the resubscribe-after-reboot path is proven by unit tests only.
